# 测试与验证

## 分层策略

| 层              | 重点                                                                             | 依赖            |
| --------------- | -------------------------------------------------------------------------------- | --------------- |
| 单元 / 属性测试 | 状态转换、规则字段及类型、图约束、会签/或签、自审、转交、超时、工单、无输入变异  | 无数据库        |
| PostgreSQL 集成 | RLS、复合租户约束、不可变记录、真实并发、幂等、事务回滚、投递去重与失败恢复      | PostgreSQL 18   |
| HTTP 集成       | Cookie、CSRF、Origin、成员停用、IDOR、SSE 重放、限流、JSON 大小和嵌套边界        | 随机端口 NestJS |
| 浏览器          | 表单、审批、会签、退回轮次、故障重开验收、现场改版本、拖拽保存、移动端、新标签页 | Chromium        |
| 初始化冒烟      | 空库迁移、受限运行角色、管理员、系统身份、四份模板、成员 CLI                     | 一次性数据库    |

`pnpm test:coverage` 针对领域核心设置 statements、branches、functions、lines 四项 90% 门槛。覆盖率不代表整个应用经过穷举验证；UI、部署和权限依赖其他分层测试。

## 测试数据库隔离

`scripts/integration.ts` 为每次运行创建随机名称数据库和随机密码的非特权角色，部署真实迁移和最小运行授权，测试结束在 finally 中删除自己创建的资源。业务服务连接受限角色，fixture 连接管理员以布置/核对数据和注入故障。运行前需启动本地 PostgreSQL，或提供有 CREATEDB / CREATEROLE 权限的测试管理连接。

E2E 同样使用一次性数据库，创建独立演示数据，启动 API 3101、Web 5174、Worker 3103，禁止复用正在演示的服务。测试依次运行，避免同一套可变流程相互干扰。不要同时启动两套 E2E，固定测试端口会冲突。测试进程被系统强制终止时 finally 无法保证执行，应由管理者检查 `ff_test_` / `ff_bootstrap_` 随机资源后清理，不对未知数据库自动执行删除。

## 并发和故障证据

- 八个相同幂等键的并发提交只生成一份申请；不同请求复用同键冲突。
- 两名或签审批人同时操作只产生一个有效决定；其余席位取消。
- 两名会签审批人竞争同一修订号，一个成功、一个 409；刷新重试后两席均正确保留。
- 撤回与同意竞争只有一种终态，没有遗留 PENDING 索引。
- 已成功审批以同一幂等键重放时，先返回保存结果，再考虑过时修订号。
- 修改并发布 v2 后，旧单继续执行 v1，新单使用 v2。
- 对通知写入注入数据库触发器故障，验证投影事务整体回滚，重试五次进入死信；移除故障后管理员重投成功。
- 故意让管理审计违反外键，验证草稿修订也回滚；管理员连接同样不能删除不可变审计。
- 超时扫描在领域测试中使用注入时钟，验证不自动代签、不破坏原会签条件。

## 常用命令

```sh
pnpm verify
pnpm format:check
pnpm test:coverage
pnpm test:integration
pnpm test:bootstrap
pnpm exec playwright install chromium
pnpm test:e2e
pnpm exec playwright show-report
pnpm audit
```

失败的浏览器测试在 `test-results` 保存截图、trace 和页面状态；HTML 报告在 `playwright-report`。这些包含测试数据，默认被 Git 忽略。仓库 `docs/screenshots` 仅保存经过人工查看的演示截图。

当前发布的执行记录见 [验证记录](validation.md)。GitHub Actions 是跨平台和容器检查的独立证据，以对应提交的实际结果为准。没有 Docker 的本地环境不能声称完成容器运行验证。
