# 五分钟演示

## 准备

按 README 初始化后登录 `admin@flowforge.demo`。工作台展示真实种子申请；生产环境不提供演示身份快捷按钮。演示前不需要清库。流程版本随发布增加，若已演示过，请将下面 v1/v2 理解为本次修改前后的两个版本。

## 修改流程并观察版本隔离

1. 员工林悦登录，创建 ¥20,000 采购申请，标题填写“研发设备采购 · 旧版本”。记下版本和地址。
2. 管理员登录，进入流程设计 → 采购申请流程。拖动部门审批节点，保存草稿并刷新，位置仍保留。
3. 点击金额判断节点，把阈值从 `1000000` 分改为 `9000000` 分，分支名称改为“金额 ≥ ¥90,000”，发布新版本。
4. 员工提交同金额“研发设备采购 · 新版本”。新单绑定刚发布的版本；旧单继续显示原版本。
5. 负责人周明远分别打开两单并同意。旧单进入财务会签；新单走默认分支并完成。
6. 财务许清禾同意旧单，状态仍为进行中；陆予安同意后完成。执行图及右侧记录展示实际分支和每位操作人。

可以同时打开申请详情，让另一浏览器账号审批，观看 SSE 自动刷新。相同浏览器的多个标签共享登录 Cookie；展示不同身份时使用独立浏览器上下文或无痕窗口。

## 退回、重提与冲突

1. 员工发起普通报销；负责人退回并填写补充原因。
2. 员工修改并重新提交。版本保持不变，轮次增加；轮次选择框可回看退回记录。
3. 同时打开两份同一申请页面，一份同意、一份撤回。过时页面会收到冲突并刷新，不会写入第二个终态。
4. 两名财务审批人同时会签，冲突的一方刷新后再次提交。不会因为重试跳过另一人的审批。

## 工单闭环

1. 员工提交设备故障，服务工程师程野认领并开始处理。
2. 工程师提交解决说明，工单进入待验收。
3. 员工选择问题未解决并填写原因；工单重开，工程师继续处理。
4. 再次解决后员工确认验收，实例完成；再次发生的问题可点击关联新申请发起新单。

## 权限和运维

- 财务部门成员查看工作台，不能看到无参与关系的研发申请；第二企业账号看不到第一企业数据。
- 管理员在组织与权限调整数据范围，后续 API 和 SSE 按当前有效身份重新校验；历史参与事项仍保留可见性。
- 当前待办超时后进入审批升级列表，只产生提醒。负责人通过转交接管，原审批策略仍有效。
- 演示中不需要等待真实 SLA：种子包含到期申请，Worker 扫描后可观察升级；领域测试另用注入时钟验证。
- 事件投递页展示管理审计。死信重投故障通过自动化测试注入验证；不要为了展示在正常演示数据库中破坏通知表。
